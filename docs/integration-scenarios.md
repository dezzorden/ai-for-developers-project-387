# Интеграционные пользовательские сценарии

Playwright запускает настоящий Chromium и проверяет совместную работу Vite frontend и NestJS backend. Каждый сценарий использует только публичный интерфейс приложения, кроме подготовки конкурентного бронирования во втором сценарии.

## 1. Полный путь бронирования

1. Гость открывает публичную страницу и видит владельца и типы событий из backend.
2. Выбирает тип события «Знакомство».
3. Выбирает первый доступный день и время.
4. Вводит имя и email и подтверждает запись.
5. Видит экран успешного бронирования.
6. Открывает административную страницу и видит созданную встречу в общем списке.

Проверяет маршруты `GET /owner`, `GET /event-types`, `GET /event-types/{id}/slots`, `POST /bookings` и `GET /admin/bookings/upcoming`.

## 2. Слот занят конкурентным запросом

1. Гость открывает расписание и видит свободный слот.
2. После загрузки страницы другой клиент бронирует этот слот через API.
3. Гость отправляет форму с уже выбранным временем.
4. Backend возвращает `409 SLOT_UNAVAILABLE`.
5. UI показывает сообщение «Слот уже занят» и не отображает ложное подтверждение.

## 3. Создание типа события владельцем

1. Владелец открывает административную часть.
2. Создает тип события с уникальным идентификатором, названием, описанием и длительностью.
3. Переходит в публичный каталог.
4. Видит новый тип события среди доступных гостям.

## Локальный запуск

```bash
npm install
npm --prefix frontend install
npm --prefix backend install
npx playwright install chromium
npm run e2e
```

Если frontend и backend уже работают на портах `5173` и `3000`, Playwright переиспользует их. В CI всегда запускаются чистые процессы.
