# Покрытие сценариев API-контрактом

| Сценарий | Операция TypeSpec | Основной результат |
| --- | --- | --- |
| Получить профиль владельца | `GET /owner` | `Owner` с часовым поясом |
| Посмотреть виды бронирования | `GET /event-types` | Название, описание и длительность каждого типа |
| Посмотреть свободное время выбранного типа | `GET /event-types/{eventTypeId}/slots` | Свободные интервалы и границы 14-дневного окна |
| Записаться на звонок | `POST /bookings` | Созданное бронирование или ошибка проверки |
| Не допустить запись вне окна | `POST /bookings` | `400 OUTSIDE_BOOKING_WINDOW` |
| Не допустить пересечение встреч | `POST /bookings` | `409 SLOT_UNAVAILABLE` после атомарной повторной проверки |
| Создать тип события | `POST /admin/event-types` | Созданный тип или `409 EVENT_TYPE_ALREADY_EXISTS` |
| Посмотреть будущие встречи всех типов | `GET /admin/bookings/upcoming` | Единый список по возрастанию `startAt` |

Контракт не содержит авторизацию, регистрацию, изменение и удаление типов, отмену бронирований и интеграции с календарями. Это соответствует ограничениям первого этапа. Управление расписанием владельца также не вынесено в API: доступное время задается конфигурацией сервера, а наружу публикуются уже рассчитанные свободные слоты.
